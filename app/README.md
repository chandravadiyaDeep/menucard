# MenuCard Android application

Flutter owner app that turns a shop profile and its dishes/prices into a ready-made digital menu, then manually publishes it as a static website ZIP.

## Architecture
- The source of truth is one schema-versioned JSON file in app-private storage.
- All business logic, validation, editing, translations, template selection, preview, backup/restore and website package generation run on-device.
- The app includes 120 ready-made menu design combinations (10 layout families × 12 color themes). Shop text and menu items are automatically bound into the selected template; owners never re-enter text for each design.
- There is no backend, remote database, API server, Worker or automatic sync.
- Customer menus are static files manually uploaded by the owner.

## Owner workflow
1. Create a shop profile.
2. Add categories, dishes, descriptions and prices.
3. Browse the ready-made design library and apply a template.
4. Preview the complete customer-facing menu using the same offline HTML/CSS/JavaScript renderer as the exported site.
5. Search and filter menu items by name, description, category and availability.
6. Export the customer-facing website package.
7. Upload the ZIP manually and share the QR code.

The selected design is stored as a stable `template_id` in the public menu JSON. Menu content remains separate, so owners can switch designs without losing their dishes or prices.

## Run locally
The Android platform directory is generated by CI. To create it on a development machine, install Flutter stable and Android SDK, then run:

    cd app
    flutter create --platforms=android --org com.deepchandravadiya --project-name menucard .
    python tool/set_android_metadata.py
    flutter pub get
    dart format lib test
    flutter analyze
    flutter test
    flutter run

## Build a local APK

    flutter build apk --release

Unless a release keystore is configured in the generated Android project, this artifact uses the default debug signing key and is for testing only.

See RELEASE.md for signing and release requirements.
